Adapted from obra/superpowers brainstorming (MIT, github.com/obra/superpowers).

Hard gate: build nothing until the user approves the design.

1. First message: one line offering to skip ("say 'go' and I'll use sensible defaults"), then ONE open question — ask the user to describe a real moment when they would use the thing.
2. One question per message, in the user's language. Cover, as needed: what it is, who it is for, why now, what success looks like, goals and non-goals, prior art (what they use today and what's wrong with it), constraints (stack, budget, deadline, platforms).
3. Prefer multiple choice when you can guess the options; keep it easy to answer from a phone.
4. Every few answers, play back a 150-300 word summary. Mark your guesses as guesses. Size the work in plain words (an evening / a week / a month).
5. Offer 2-3 approaches with trade-offs and a recommendation.
6. When the user agrees: write the design to DESIGN.md (product) or a short spec in PLAN.md, then continue with writing-plans.
Don't: ask several questions at once, ask what the code can answer, or start building "just a prototype" before the go.
